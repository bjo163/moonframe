# Primitive provider comparison: paper review and spike gate

**Reviewed:** 2026-10-25 (Asia/Jakarta). Source review and isolated browser spike. Browser fixture lives only under the operating-system temporary directory; no provider dependency, app source, or package manifest was added to Moonframe. The fixture is disposable and is not a supported project tool.

## Equal-fixture plan and evidence status

The fixture implements identical Dialog, Select, editable Combobox, and nested action Menu tasks in Base UI, React Aria, and Radix. The Radix Combobox is a custom ARIA composition; content/data and interaction outcomes are fixed. It uses Chromium 156 via Playwright; it does not include manual assistive technology, OS forced-colors, or Next.js.

| Dimension | Source-review finding | Runtime outcome |
|---|---|---|
| Keyboard and focus restoration | All candidates document accessibility/focus support at the component level; Radix Combobox is custom fixture code. | **Passed for tested cases:** 18 Playwright keyboard/focus checks, 6 per provider: Dialog accessible label/Escape/trigger focus return; Dialog tab containment and outside dismissal; keyboard Select selection and controlled value; Select typeahead with Enter confirmation; editable Combobox filtering and keyboard selection; nested action Menu arrow navigation, activation and focus return. The separate 3 ARIA role/name smokes make 21 browser checks total (7 per provider). Modal focus cycles allow 50 ms for focus guards to settle. Further edge cases remain untested. |
| ARIA and semantics | Candidate docs describe semantic patterns, but composition correctness depends on fixture markup and labels. | **Smoke passed:** each provider's controls exposed expected accessible names and roles (Base UI/Radix Select as combobox; React Aria Select as button; City as combobox; filtered Bandung as option; nested menu as menu/menuitem). Radix's custom combobox passed these smoke assertions but has not had manual AT/APG review. |
| RTL and internationalization | React Aria documents broad internationalization; Radix advertises RTL support; Base UI behavior is component-specific. | **Basic smoke passed:** set document direction to RTL in Chromium; editable Combobox keyboard selection and Dialog open/Escape worked for all three providers. Popup placement, submenu arrow semantics, locale-sensitive typeahead, and broader scripts/locales remain untested. |
| Forced colors / reduced motion | No cross-candidate outcome is established by this review. | **Emulation smoke passed:** Chromium reported `forced-colors: active` and `prefers-reduced-motion: reduce`; core Combobox and Dialog interactions remained available for all three. No Windows system forced-colors/manual visual audit or motion animation audit was performed. |
| SSR and hydration | Framework compatibility cannot be inferred from client components or portal documentation alone. | **Passed for isolated React SSR fixture:** `renderToString` produced closed-dialog markup for all three providers; Chromium hydration preserved the fixture, emitted no console/page errors, and opened the Dialog. This was not a Next.js integration test; framework-specific routing, streaming, portals, and production deployment remain unknown. |
| Styling and composition | Base UI `render`, Radix `asChild`, and React Aria hook/component models are structurally different. | **Not tested.** Check class/style/state exposure, DOM ref forwarding, event order/cancellation, nested button safety and custom elements. |
| Dependencies and bundle | Exact fixture package versions are pinned by its temporary lockfile. | **Measured in separate production builds:** Base UI JS 394.73 kB (gzip 127.56 kB); React Aria JS 431.15 kB (gzip 132.11 kB); Radix + custom Combobox JS 303.99 kB (gzip 95.66 kB); common CSS 7.27 kB (gzip 2.09 kB). Same Node/Vite/Tailwind/React versions and content; each JS number includes React/app runtime. These are fixture comparisons, not production library size guarantees. Full isolated transitive install footprints remain unmeasured. |

The browser harness ran on 2026-10-25 using Node 24.22.1 LTS, Playwright 1.64.1 and Chromium 156: 21 keyboard/focus/ARIA checks (7 per provider), 3 RTL/media smokes, and 3 SSR/hydration checks passed. Separate Vite/Tailwind production builds reported above. Vite emitted module-level `use client` warnings because this generic client bundle is not an SSR framework build. A prior JSDOM-only SSR attempt failed because browser `CSS` APIs were unavailable in that harness; the successful server-render + real Chromium hydration check supersedes that harness attempt for this isolated fixture only.

## Decision and blocker

**Decision: no provider selected.** MF-003 established a synthetic first consumer and recommends MoonWitness XIV board for a later approved real-app smoke. All three candidates now have equal-fixture basic keyboard/focus, RTL/media emulation, isolated SSR/hydration, and per-option bundle evidence; Radix's Combobox is custom fixture code, which removes the catalog coverage gap but adds Moonframe implementation/maintenance risk. Its smaller measured bundle cannot offset missing custom-combobox AT/APG review. Manual screen-reader/AT review, Windows forced-colors visual review, broad locale/direction behavior, framework-specific SSR, deeper keyboard/APG coverage, transitive package footprint, and maintainer review remain outstanding. This is partial runtime evidence; MF-005 stays open.

The repository CI and local runtime are pinned to Node 24.22.1 LTS via `.nvmrc`; the fixture uses that same Node version in a temporary isolated directory. Keep the issue open and ADR proposed until outstanding coverage and maintainer review exist. No dependency, public API, or production consumer changes are included in this research.
