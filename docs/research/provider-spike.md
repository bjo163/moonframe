# Primitive provider comparison: paper review and spike gate

**Reviewed:** 2026-10-25 (Asia/Jakarta). Source review and isolated browser spike. Browser fixture lives only under the operating-system temporary directory; no provider dependency, app source, or package manifest was added to Moonframe. The fixture is disposable and is not a supported project tool.

## Equal-fixture plan and evidence status

The fixture implements identical Dialog, Select, editable Combobox, and nested action Menu tasks in Base UI, React Aria, and Radix. The Radix Combobox is a custom ARIA composition; content/data and interaction outcomes are fixed. It uses Chromium 156 via Playwright; it does not include manual assistive technology, OS forced-colors, or Next.js.

| Dimension | Source-review finding | Runtime outcome |
|---|---|---|
| Keyboard and focus restoration | All candidates document accessibility/focus support at the component level; Radix Combobox is custom fixture code. | **Passed for tested cases:** 18 Playwright keyboard/focus checks, 6 per provider: Dialog accessible label/Escape/trigger focus return; Dialog tab containment and outside dismissal; keyboard Select selection and controlled value; Select typeahead with Enter confirmation; editable Combobox filtering and keyboard selection; nested action Menu arrow navigation, activation and focus return. The separate 3 ARIA role/name smokes make 21 browser checks total (7 per provider). Modal focus cycles allow 50 ms for focus guards to settle. Further edge cases remain untested. |
| Additional APG keyboard edges | The [WAI-ARIA APG Menu and Menubar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/) describes closing a nested menu and returning focus to its opener; Escape also dismisses the top-level menu. | **Temporary exploratory rerun on Node 24.22.1 / Playwright 1.64.1 / Chromium 156:** Select Home/End, nested-menu Left Arrow, and top-level-menu Escape passed for all three providers. In the default fixture, nested-menu Escape closed only that submenu and returned focus to its parent item for Base UI and React Aria; Radix closed the root menu on the first Escape and returned focus to the root trigger. A separate Radix wrapper experiment used the documented `SubContent.onEscapeKeyDown`, controlled `Sub.open/onOpenChange`, `preventDefault()`, and explicit focus restoration; the nested submenu then closed while the parent remained open and focus returned to its opener. This covers the observed difference with wrapper code, not a complete APG or AT audit. |
| ARIA and semantics | Candidate docs describe semantic patterns, but composition correctness depends on fixture markup and labels. | **Smoke passed:** each provider's controls exposed expected accessible names and roles (Base UI/Radix Select as combobox; React Aria Select as button; City as combobox; filtered Bandung as option; nested menu as menu/menuitem). Radix's custom combobox passed these smoke assertions but has not had manual AT/APG review. |
| RTL and internationalization | Base UI provides a [`DirectionProvider`](https://base-ui.com/react/utils/direction-provider); React Aria derives direction from [`I18nProvider`](https://react-aria.adobe.com/I18nProvider); Radix Dropdown Menu accepts direction and documents reading-direction-dependent submenu keys ([docs](https://www.radix-ui.com/primitives/docs/components/dropdown-menu)). | **Basic keyboard smoke passed:** set `<html dir="rtl">` before React boot; configured Base UI `DirectionProvider direction="rtl"`, React Aria `I18nProvider locale="ar-AE"`, and Radix `dir="rtl"`. Editable Combobox keyboard selection, Dialog open/Escape, and nested Menu opening with ArrowLeft and closing with ArrowRight passed for all three. This does not measure visual popup placement, mirrored layout, locale-sensitive typeahead, or broader scripts/locales. |
| Forced colors / reduced motion | OS-level rendering and motion behavior are not established by browser emulation. | **Emulation smoke passed:** Chromium reported `forced-colors: active` and `prefers-reduced-motion: reduce`; core Combobox and Dialog interactions remained available for all three. No Windows system forced-colors/manual visual audit or motion animation audit was performed. |
| SSR and hydration | Framework compatibility cannot be inferred from client components or portal documentation alone. | **Passed for isolated React SSR fixture:** `renderToString` produced closed-dialog markup for all three providers; Chromium hydration preserved the fixture, emitted no console/page errors, and opened the Dialog. This was not a Next.js integration test; framework-specific routing, streaming, portals, and production deployment remain unknown. |
| Styling and composition | Base UI `render`, Radix `asChild`, and React Aria component APIs differ; Radix's editable Combobox is Moonframe-owned. | **Basic composition smoke passed:** on each Dialog trigger, consumer class and `data-*` prop were preserved, a DOM ref attached, and activation callback fired while opening the Dialog. This does not test style-state APIs, callback ordering/cancellation, nested-button safety, other components' ref/event composition, or custom elements. |
| Dependencies and bundle | Temporary lockfile pins exact versions; the bundle fixture imports each candidate's Dialog, Select, Menu, and Combobox task. | **Measured in separate production builds:** Base UI JS 394.95 kB (gzip 127.64 kB); React Aria JS 431.37 kB (gzip 132.19 kB); Radix + custom Combobox JS 304.20 kB (gzip 95.74 kB); common CSS 7.27 kB (gzip 2.09 kB). Each JS number includes React/app runtime. Lockfile runtime-dependency closure (root + `dependencies` + `optionalDependencies`, excluding peer/dev dependencies) was Base UI 9 packages / 12,031,001 installed file bytes; React Aria 13 / 30,665,126 bytes; aggregate `radix-ui` 74 / 5,466,242 bytes. These on-disk bytes include shipped package files such as types/locales, are not compressed download sizes, and depend on the exact lock/install layout. Radix's aggregate has the broadest package graph although this fixture tree-shook to the smallest JS output. None of these are production consumer guarantees. |

The browser harness ran on 2026-10-25 using Node 24.22.1 LTS, Playwright 1.64.1 and Chromium 156: 24 keyboard/focus/ARIA/composition checks (8 per provider; six keyboard/focus cases, one role/name smoke, and one composition smoke), 3 RTL/media smokes, and 3 SSR/hydration checks passed. Separate Vite/Tailwind production builds and lockfile dependency-closure measurements are reported above. Vite emitted module-level `use client` warnings because this generic client bundle is not an SSR framework build. A prior JSDOM-only SSR attempt failed because browser `CSS` APIs were unavailable in that harness; the successful server-render + real Chromium hydration check supersedes that harness attempt for this isolated fixture only. An initial concurrent RTL rerun hit the already-used local port; the sequential rerun passed all three provider cases.

The subsequent exploratory APG-edge run added twelve temporary Playwright cases: all three Select Home/End, nested-menu Left Arrow, and top-level-menu Escape cases passed; nested-menu Escape passed for Base UI and React Aria, while Radix failed the expected submenu-only close/parent-item focus behavior (11/12 pass). A separate temporary wrapper experiment then ran the full 36-case equal-behavior suite with Radix's nested submenu Escape corrected; all 36 passed. The wrapper used the documented `SubContent.onEscapeKeyDown` hook, controlled submenu state, and explicit focus restoration to the parent item. The experiments live only in the temporary fixture and do not change the original 24-check baseline above. The WAI-ARIA APG says Escape should close the menu containing focus and return focus to its opener, which in this nested-menu case is the parent menu item. The Radix difference is therefore addressable through the documented API, at the cost of Moonframe-owned wrapper behavior; it is not evidence of a default behavior pass. This keeps provider selection open pending maintainer review and broader manual testing.

## Decision and blocker

**Decision: no provider selected.** MF-003 established a synthetic first consumer and recommends MoonWitness XIV board for a later approved real-app smoke. All three candidates now have equal-fixture basic keyboard/focus, RTL/media emulation, isolated SSR/hydration, composition smoke, bundle and lockfile dependency-closure evidence; Radix's Combobox is custom fixture code, which removes the catalog coverage gap but adds Moonframe implementation/maintenance risk. Its smaller measured bundle cannot offset missing custom-combobox AT/APG review and its wider aggregate package graph. Default Radix nested-submenu Escape closed the root menu, but a documented-API wrapper restored submenu-only close and parent-item focus; this adds Moonframe-owned behavior and needs broader manual review. Manual screen-reader/AT review, Windows forced-colors visual review, broad locale/direction behavior, framework-specific SSR, deeper keyboard/APG coverage, production consumer footprint and maintainer review remain outstanding. This is partial runtime evidence; MF-005 stays open.

The repository CI and local runtime are pinned to Node 24.22.1 LTS via `.nvmrc`; the fixture uses that same Node version in a temporary isolated directory. Keep the issue open and ADR proposed until outstanding coverage and maintainer review exist. No dependency, public API, or production consumer changes are included in this research.
