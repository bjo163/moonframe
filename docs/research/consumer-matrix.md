## Recommendation and constraints

Use a **synthetic consumer fixture** as the first test consumer. This avoids selecting or modifying a production app before package exports, provider, and support policy are approved. For a real-app smoke after those gates, recommend MoonWitness XIV board because its manifest/config expose React, Next SSR/standalone output, Tailwind, and pnpm workspace constraints in one candidate. This is a recommendation, not maintainer authorization to migrate or install into that repository.

No runtime versions were executed or resolved, no application was built, and no browsers or RTL modes were tested. Browser support, installed browser versions, package-manager runtime version, lockfile-resolved dependency versions, deployment-specific SSR behavior, and RTL behavior are **unknown**. Do not infer a support promise from framework declarations. A future compatibility check should record a clean install/build, SSR/hydration result, keyboard/AT sampling, LTR/RTL, and a documented browser/version matrix. Preserve package isolation and verify provider advisories/licenses before introducing dependencies; do not copy consumer secrets or production data into fixtures.

## Evidence boundaries

- All linked source paths are pinned to commit snapshots; branch movement cannot silently change the cited evidence.
- “Not declared” means absent from the inspected manifest/config only; it does not prove a tool or behavior is unused elsewhere in the repository.
- Repository contents and installed environments were not cloned or executed. Private repositories were not audited.
- This inventory does not select a primitive provider, approve package support, or authorize production-consumer changes.
